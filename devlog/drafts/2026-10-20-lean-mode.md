# 2026-10-20: lean mode and web UI

The owner changed how the build runs and what v0.1 includes. The full agent process burned usage while the product still could not index and search a video, so lean mode starts until the MVP demo works. v0.1 gets a web UI. The MVP is general video only.

## What happened

- **Lean mode** ([ADR 0014 draft](../../docs/adr/drafts/0014-lean-mode-ui-robotics.md)). One `feature-builder` per approved spec, one `reviewer` pass per PR. No spec-critic, council or test-auditor by default. Test sets are acceptance plus dangerous cases, about 15 to 35 per spec.
- **Models.** Opus only for decisions (planner, lead). Sonnet for every other coding, test and review subagent. Haiku for scribe.
- **Decisions.** The lead writes decision cards. The owner sees only spend above about $5, credentials and security.
- **Web UI in v0.1.** `tapesift serve` moves up from v0.3. Spec 40 is being written.
- **Later, not v0.1.** Robotics datasets (for example Open X-Embodiment) are a future use case. No spec.
- **Status.** The v0.1 build is in lean mode. Done: #21, M1 (#25), v0.1 decisions (#37). In progress: E5 (#28) and E7 runner phase 1 (#30). Next: E3, E4, E6, web UI, E7 phase 2.
- **Not changed yet.** The "Claude Code only" block in `CLAUDE.md` still describes the full process. The lean text is in ADR 0014 for the owner or lead to apply.

## Numbers

- Agents per feature, before: 5 to 8. After: 2 (one builder, one reviewer), plus the lead.
- Tests: the suite passed 600+ before this change. Per-spec test sets drop to about 15 to 35.
