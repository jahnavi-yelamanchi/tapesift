# 2026-10-17 (draft)

Decision: asset IDs use a head/tail hash with a `tsid1:` prefix by default, and a plain sha256 on request (ADR 0012). Over a `sha256:` prefix on the partial hash.
Why: default ingest reads at most 16 MiB per file (8 MiB at each end plus the size), so it stays fast on network storage. A `tsid1:` prefix says what was hashed and can be versioned. A `sha256:` prefix on a partial hash looks like corruption to `shasum -a 256`.
Cost: two ID forms to explain. Equal-size headerless captures can collide on the default ID; E7 confirms any DUPLICATE with a full hash before it is reported.
Revisit if: a NAS benchmark shows the two 8 MiB reads are slow. ADR: docs/adr/0012-asset-id-scheme.md

Decision: Python 3.12 is the floor, not 3.11 (ADR 0011).
Why: av>=19.0.1 and numpy>=2.5.4 both require 3.12. Keeping 3.11 meant a split lock, so two PyAV and numpy versions under test instead of one.
Cost: users who install into an existing 3.11 environment are dropped. uvx fetches a 3.12 interpreter for those who lack one.
Revisit if: a target platform pins 3.11. ADR: docs/adr/0011-python-floor-3-12.md

Broke: `Frame` stopped being read-only after pickling. Caught in review of PR #10.
Cause: the spec set `writeable = False` on the array. Unpickling builds a new array that is writeable again. A view also kept its base array, so the base could still change the pixels.
Fix: `Frame` and `AudioChunk` copy a view and set the flag in `__post_init__`, and `__reduce__` reruns that on load (src/tapesift/media/types.py, commit 09d69fa). Two more review-fix commits followed (27b8921, 82c6937).
Lesson: code copied verbatim from an approved spec was still wrong. Pickling and view aliasing are now tested (82c6937), not just read.
