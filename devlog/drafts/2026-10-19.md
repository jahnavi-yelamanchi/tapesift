# 2026-10-19 (draft)

Phase 0 is closed. v0.1 "works on your laptop" started today. The goal for the two weeks: point tapesift at a 10-minute talk on a laptop CPU and search it.

## What happened

- **Plan.** A v0.1 planning doc was written from the spec, the ADRs and the open issues. It found 10 conflicts in the spec. Each one became an owner card. The cards are numbered Q1 to Q11 so they do not collide with the spec's D1 to D15.
- **Security first (#21).** Before any v0.1 feature, the owner asked for the file-format lock-down. The media code opened every file by path, so FFmpeg could read more than the file the user named:
  - a text file named `.mp4` could make FFmpeg read its neighbours through a concat list;
  - an `.m3u8` could pull in segments;
  - an image sequence could be read through `image2`;
  - a named pipe (FIFO) hung forever.
  The #21 spec ([docs/specs/21-safe-opener.md](../../docs/specs/21-safe-opener.md)) took seven cards. The owner approved all seven with the recommended option on 2026-10-19. The fix: open every file through a checked file descriptor, never a path, and allow nine containers only.
- **Q1 measurement.** The question was whether torch belongs in the base install. The install was timed on GitHub Actions with an empty cache. Run: https://github.com/jahnavi-yelamanchi/tapesift/actions/runs/39347647667
  - Linux: lean 4 s and 778 MB; full 33 s and 6.1 GB.
  - macOS: lean 3 s and 479 MB; full 10 s and 1.1 GB.
  Both are under the 120 s bar. The Linux full install is mostly CUDA wheels. The writeup is on branch `exp/q1-install-timing`, file `docs/experiments/2026-10-19-q1-install-timing.md`. That branch is kept and not merged.
- **Owner answers.** Recorded in the 2026-10-20 ADR draft ([0013](../../docs/adr/drafts/0013-v01-decisions.md)). The owner made the Q1 call later, on 2026-10-20.
